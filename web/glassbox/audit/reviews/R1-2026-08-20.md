## Contract change, announced

`CONTRACT_VERSION` moved `v0.1.0` → `v0.2.0`. `BuildIdentity` gained a
required `parameters: { lm, encoder }`.

Reason: §9 requires a model parameter figure on screen, and typing `802.816`
into a component would have been an invented number with no provenance.
`.agents/skills/a7-fpga-gate/SKILL.md` forbids summing the two counts and names
"1.6M parameter AI" a forbidden phrase, so the schema deliberately has **no
`total` field**, and a stray `total` is stripped by parse. A test asserts both.

Both lanes must react. The frontend already has: the fixture and the top-bar
story were updated, and `tsc` caught the story as a hard error rather than
letting it drift. The backend lane has no code yet, so it inherits the field.

## Findings raised during the turn

**A test passed for the wrong reason and had to be fixed.** The first
reduced-motion test asserted the collapsed duration but was fed by
`test.use({ reducedMotion: "reduce" })`, which did not reach the page:
`matchMedia(...).matches` returned `false`. Had the CSS been wrong, that test
would still have failed — but had the CSS been *right and the emulation absent*,
a naive version without the matchMedia assertion would have passed while
verifying nothing. Replaced with `page.emulateMedia` plus an explicit assertion
that the emulation landed.

**Two shell tests were stale, not broken.** `/` now redirects to Tab 1 once an
interaction is chosen, so assertions written against the R0 summary card on `/`
failed. They were retargeted to the routes where that content now lives, and a
new test pins the redirect itself. This is the correct response to a deliberate
behaviour change; loosening the selectors would have hidden it.

**Four selectors matched more than one element.** In every case the second
match was the §28 screen-reader table or caption, which is intended. Fixed by
scoping to the owning card or by exact, case-sensitive matching — not by
relaxing the assertion.
