`NATIVE_AI_GLASSBOX_UXUI_SPEC.md` §5, §6, §8.1, §9, §10, §30, §31, §32.

| Field | Decision |
|---|---|
| Screen job | **Tổng quan**: answer "AI đang làm gì ngay bây giờ?" in under five seconds. **Tương tác**: read the conversation as a normal product, then step inside one message. |
| Primary user and action | Tổng quan: a curious end user scanning state, whose action is to open the stage that interests them. Tương tác: the same user reading an answer, whose action is "Xem bên trong tương tác này". |
| Content hierarchy | Tổng quan: what was asked → where the process is now → what changed → how long each stage took. Tương tác: the answer → its metadata → the inspector, in that order, because the product is a chat first and an instrument second. |
| Navigation and controls | Both screens inherit the §6 shell. Tổng quan's pipeline is itself navigation. Every control resolves to a route that exists today; the §9 "Replay" button is **omitted until R6** rather than shipped inert. |
| Visual language | Existing tokens only. Pipeline stages carry the `PHASE_TOKEN` colour plus a state glyph. Waterfall bars are `PHASE_TOKEN` on `surface-2`. No new colour, no new radius. |
| Required states | Interaction selected / not selected; stage complete, active, waiting, error; learning happened / no update needed; answer present / absent; memory hit / miss; partial traceability. |
| Responsive behavior | ≥1440px: three columns on Tổng quan, conversation plus docked inspector on Tương tác. 1280px: Tổng quan collapses to two columns with the state panel beneath; the inspector becomes a drawer per §27. |
| Forbidden defaults | No "AI brain" illustration. No interchangeable KPI card row. No generic "View details" CTA. No animated pipeline that moves without recorded data (§32.9, §8.2 last line). No token count or parameter figure typed as a literal into JSX. |
| Acceptance criteria | A first-time reader can name the current stage and whether learning happened without scrolling. Every figure carries a provenance badge. The animated pipeline stops animating under `prefers-reduced-motion`. Both screens report the same `interactionId` as the shell. |

## Decisions that needed a judgement call

**The §9 event banner is conditional, not decorative.** §9 says do not show it
unless backed by actual telemetry. It renders only when a `LearningEvent` with
`updateEnabled` exists, and its numbers come from that event. Interaction 1841
has no learning event, so the banner is absent there rather than reworded.

**Parameter counts come from the contract, not from the JSX.** §9 shows
"802.816 tham số". `.agents/skills/a7-fpga-gate/SKILL.md` forbids summing the
LM and encoder counts and names "1.6M parameter AI" a forbidden phrase, so the
contract gains a `parameters` object with the two counts kept separate and no
total field. Typing `802.816` into a component would have been an invented
figure with no provenance.

**`/` stops showing a summary card.** R0 shipped a "Các khung nhìn chi tiết"
card on `/` that explained that tabs were coming. That is exactly the filler
card the anti-ui-slop finish gate rejects. With Tab 1 in place, `/` redirects
to `/tong-quan` once an interaction is chosen and remains the §26 picker
otherwise.

**The pipeline animation is driven by stage state, not by a timer.** A stage
pulses only while its state is `active`. With a recorded fixture every stage is
already `complete`, so nothing moves — which is correct, and is why the
`DangChay` story exists to exercise the moving case.
